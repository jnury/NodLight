# NodLight Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Windows always-on-top strip that shows one card per Alacritty window running Claude Code or Codex, with live Working / Waiting / Idle status, and focuses that window on click.

**Architecture:** Claude Code and Codex hooks call a tiny AOT console helper (`nodlight-hook.exe`). It resolves its Alacritty ancestor process and sends one JSON line over a named pipe to the WPF deck. The deck reduces events into per-window cards (pure logic in `NodLight.Core`), watches windows, foreground changes and transcripts, and renders the strip.

**Tech Stack:** .NET 10 SDK (10.0.403 installed), C#, WPF (`net10.0-windows`), xUnit, System.Text.Json (source-generated for AOT), Win32 P/Invoke.

**Spec:** `docs/superpowers/specs/2026-10-27-nodlight-design.md`

## Global Constraints

- Windows 11 only; Alacritty 0.17; one `alacritty.exe` process per window (verified).
- Agents: Claude Code `claude.exe` (native, 2.1.311) and Codex CLI 0.164 (npm wrapper `node.exe` → `codex.exe`).
- The helper must **never** block, prompt, write to stdout, or exit non-zero. Pipe connect+write timeout: **200 ms**.
- Never modify Codex `notify` in `~/.codex/config.toml`. Codex hooks go in `~/.codex/hooks.json`.
- Installing hooks: back up each file first (`<file>.nodlight.bak`), preserve all other keys and hooks, re-running is a no-op, uninstall removes only entries whose command contains `nodlight-hook`.
- Helper installed to `%LOCALAPPDATA%\NodLight\nodlight-hook.exe`; hook commands use **forward slashes** and a quoted path, e.g. `"C:/Users/jnury/AppData/Local/NodLight/nodlight-hook.exe" claude Stop` (works whether the agent runs hooks through cmd, pwsh or Git Bash).
- Cards keyed by Alacritty top-level window handle (HWND). One card per window.
- Strip: right edge of the primary monitor's work area, always on top, floating (no AppBar), dark, not in taskbar/Alt-Tab.
- Status colours: Waiting = orange `#FAB387` (loudest), Working = green `#A6E3A1`, Idle = grey `#6C7086`.
- No sound, toasts or flashing.
- Every command handed to Julien is PowerShell 7.

## Review Focus

1. **PID reuse in the parent chain**: a parent PID that now belongs to a newer process must stop the walk instead of attributing the event to the wrong window → test in Task 3.
2. **Nested agent runs** (`claude -p` / `codex exec` from inside a session) must not change the card → test in Task 3 (chain) and Task 7 (helper drops it).
3. **Malformed or partial config files** (`settings.json` with comments/trailing data, empty `hooks.json`): install must refuse and leave the file untouched rather than overwrite it → test in Task 4.
4. **Deck not running**: the helper exits 0 within ~200 ms and prints nothing → test in Task 6 (client timeout) and manual check in Task 7.
5. **Window closed or reused while a card exists**: the card disappears; a later event from a new window creates a fresh card → test in Task 8.

### Task 3: Parent-chain resolution

**Files:**
- Create: `src/NodLight.Core/ProcessChain.cs`
- Test: `tests/NodLight.Core.Tests/ProcessChainTests.cs`

**Interfaces:**
- Produces:
  - `sealed record ProcessInfo(int Pid, int ParentPid, string Name, DateTime StartUtc)`
  - `interface IProcessTree { ProcessInfo? Get(int pid); }`
  - `sealed record ChainResult(int? AlacrittyPid, bool Nested)`
  - `static ChainResult ProcessChain.Resolve(int startPid, IProcessTree tree)`

Algorithm: walk parent links from `startPid` and compare names case-insensitively. Count the processes named `claude.exe` or `codex.exe`. Stop at the first `alacritty.exe`, or after 64 steps, or when a process is missing. Also stop when a parent's `StartUtc` is later than its child's, which means the PID was reused; in that case `AlacrittyPid` is null. `Nested` is true when the count is greater than 1.

  - `Claude_print_inside_session_is_nested`: hook→claude.exe→bash→claude.exe→pwsh→alacritty gives Nested true.
  - `Pid_reuse_stops_walk`: the parent's StartUtc is after the child's, so AlacrittyPid is null.
  - `No_alacritty_returns_null`: the walk ends at explorer.exe.
  - `Cycle_is_bounded`: two processes that are each other's parent return null without hanging.

### Task 9: The strip (WPF app)

**Files:**
- Create: `src/NodLight.App/Native.cs`, `WindowService.cs`, `CardViewModel.cs`, `DeckViewModel.cs`, `StripWindow.xaml(.cs)`; modify `App.xaml(.cs)`

**Interfaces:**
- Consumes: `PipeServer`, `SessionStore`, `TranscriptTail`, `InterruptDetector`, `TimeFormat`.
- Produces:
  - `WindowService` with these members:
    - `long? FindMainWindow(int pid)`: the visible, unowned top-level window of that process.
    - `string GetTitle(long hwnd)`
    - `bool IsAlive(long hwnd)`
    - `void Focus(long hwnd)`
    - `event Action<long>? ForegroundChanged`, raised via `SetWinEventHook(EVENT_SYSTEM_FOREGROUND, WINEVENT_OUTOFCONTEXT)`
  - `CardViewModel` exposes `Title`, `AgentBadge` (`"claude"`/`"codex"`), `StatusLine` (`"Waiting · 4 min · webapp"`), `Detail` (shown only when Waiting) and `Brush`.

Behaviour:
- `PipeServer` events are marshalled to the dispatcher, then `FindMainWindow(e.AlacrittyPid)` runs and `store.Apply(e, hwnd)` is called. Events with no window are dropped.
- A 1 s `DispatcherTimer` does three things: it removes cards whose window is dead, refreshes titles and status-line times, and polls the `TranscriptTail` for each card (one tail per transcript path), calling `store.Interrupted` on a match.
- `ForegroundChanged` calls `store.Foreground`. The deck ignores its own window.
- Clicking a card calls `Focus`: if the window `IsIconic`, call `ShowWindow(SW_RESTORE)`, then `SetForegroundWindow`. If that returns false, attach to the current foreground thread with `AttachThreadInput` and retry.
- Window settings: `WindowStyle=None`, `Topmost=True`, `ShowInTaskbar=False`, extended style `WS_EX_TOOLWINDOW`, width 240 px, height equal to the primary work area, docked right. The background is `#11111B` and card backgrounds are `#232334`, with a 3 px left border in the status colour. Waiting cards use the `#3A2C22` background. Match mockup C.
- Card text: the title is ellipsized on one line; the status line is smaller and grey; the detail is orange and shown only when Waiting.
- Right-click on the strip opens a context menu with "Install hooks", "Remove hooks" and "Exit". Task 10 wires these items up.
- Only one deck runs at a time: a named `Mutex` `NodLight.Single.<UserName>` enforces this; a second launch exits.

- `Install` copies the bundled `nodlight-hook.exe`, which the App build copies to its output, to `%LOCALAPPDATA%\NodLight\` when it's missing or differs. Then it runs `InstallFile` for `%USERPROFILE%\.claude\settings.json` (Claude) and `%USERPROFILE%\.codex\hooks.json` (Codex).
- `EnsureInstalled` runs `Install` when either file lacks NodLight hooks, then shows one message box: "NodLight hooks installed. In Codex, run /hooks once and trust the NodLight hooks." It never touches `config.toml`.
- If `InvalidDataException` is thrown, show which file couldn't be parsed and leave it untouched.
- `Remove` runs `UninstallFile` on both files.
- The App csproj publishes the Hook project's output next to itself, using a `ProjectReference` with `ReferenceOutputAssembly=false` plus a post-publish copy, or a build target. Builder's choice.
